# /usage-insights — エージェント利用ログの傾向分析

引数: `$ARGUMENTS`（任意。例: `--days 90`、`--month 2026-07`、`--source claude`。空なら既定期間 = 先月1日〜今日）

数値の計算は **すべて CLI に任せる**。自分で JSONL を読んだり電卓を叩いたりしない。
このスキルの仕事は、出てきた表を読んで **示唆に変換すること**。

## ステップ 1: 集計を取る

リポジトリルート（このスキルを持つ `local-agent-usage`）で:

```bash
npm run build --silent && node dist/cli.js --insights $ARGUMENTS
```

`dist/` は gitignore されているので、clone 直後は `npm install` も先に走らせる。

- 期間指定が無ければ、トレンドを見るために `--days 90` 程度を足してよい（1〜2か月だと前月比が出ない）。
- 機械処理したいときは `--json` を足すと同じ内容が JSON で出る。
- `npm run build` はソース未変更ならすぐ終わる。失敗したらビルドエラーなので、内容をそのまま報告する。

## ステップ 2: 読む

出力に含まれるセクションと、そこで見るべき点:

| セクション | 見るポイント |
| --- | --- |
| Total / Mix / Rate | cache read の比率（高いほど「同じ文脈の読み直し」がコストの主因）、output/call（生成の粒度） |
| By agent | エージェント間のシェア推移。first/last が離れていれば乗り換えのサイン |
| Monthly + MoM | 絶対量だけでなく **tok/day** と **cacheR%** を見る。量が増えてコストが減っていれば効率改善 |
| Weekly + WoW | 直近の立ち上がり／失速。当月・当週は途中集計なので前期比をそのまま断定しない |
| Projects | 上位の集中度。`.claude/worktrees/`、`/private/var/folders/...`、`tmp/` 配下が上位に来ていたら使い捨て環境でキャッシュが効いていない疑い |
| Models | first/last でモデル移行の時期。旧モデルが残り続けていないか |
| Hour of day / Weekday | 稼働の型（夜型・週末型など）。運用やレビュー体制の話につながる |
| Session size | p50 と max の開き、top 10% シェア。集中していれば長時間セッションの分割が最大の削減レバー |

## ステップ 3: 示唆にする

レポートは日本語。表を貼り直すだけにしない。**必ず次を含める**:

1. **全体像** — 期間・総トークン・概算コストを 2〜3 行、または小さな表で。
2. **傾向 3〜5 個** — それぞれ「事実（数字つき）→ 解釈」の順。単なる増減報告で終わらせない。
3. **アクション候補** — 効きそうな順に。効果の大きさ（何 % / 何ドル相当か）を数字で添える。

必ず添える注意書き:

- コストは **全エージェント・全モデルに同一レートを当てた概算**。請求額ではない。
- 当月・当週は途中集計。前期比を語るときは明示する。
- ログが残っている範囲しか見えない（古いセッションログが消えていれば過小評価）。

## グラフで見せたいと言われたら

`--insights` を付けずに通常のレポートを生成すれば、同じ軸が
チャートになった Insights セクション付きの HTML が出る:

```bash
npm run build --silent && node dist/cli.js --days 90 --open false
```

モデル構成の週次推移 / プロジェクト別 / セッション集中度（ローレンツ曲線）/
週次効率トレンド / 曜日×時間帯ヒートマップ が入る。テキスト版と数字は同じ。

チャートには**解釈文が入っていない**（データが変われば陳腐化するため意図的）。
「グラフを見て」と言われた場合も、示唆はこのスキルが `--insights` の数字から
毎回書く。HTML に書いてある文言を読み上げるのではない。

## やらないこと

- 数字の推測・補完。CLI が出していない値を勝手に作らない。
- 全プロジェクトの羅列。上位と「その他まとめ」で足りる。
- 改善提案の水増し。効きそうなものだけを、根拠の数字つきで。
